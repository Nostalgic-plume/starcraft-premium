# 电商离线数仓项目答辩

## 一、项目概述

基于 **Shop 电商系统** 的离线数仓，T+1 产出经营指标报表。MySQL 业务库 → Hive 数仓（4 层）→ MySQL 报表库，全流程 **Azkaban** 调度。

---

## 二、整体技术栈

| 层级 | 技术 | 版本 | 用途 |
|------|------|------|------|
| **业务数据库** | MySQL | 5.7 / 8.0 | Shop 电商系统数据源（localhost:3306/shop） |
| **模拟数据生成** | shop-data-mocker（纯 Java） | JDK 22、Maven | 每日生成增量业务数据（用户、商品、订单等） |
| **数据导入/导出** | Apache Sqoop | 1.4.7 | MySQL ⇄ Hive 数据传输 |
| **分布式存储** | Hadoop HDFS | 3.x | 数仓底层存储 |
| **数仓计算引擎** | Apache Hive | 3.1.3 | SQL 化 ETL 加工 |
| **计算执行引擎** | MapReduce / Spark | MR + Hive-on-Spark | Hive SQL 底层执行 |
| **任务调度** | Azkaban | 3.x | 每日全链路 ETL 调度 |
| **报表数据库** | MySQL | — | ADS 结果落库（shop_ads 库，供前端查询） |
| **数据可视化** | Vue + ECharts | — | 前端报表展示 |

### 数据流向

```
shop-data-mocker ──▶ MySQL shop ──Sqoop──▶ Hive ODS ──▶ DWD ──▶ DWS ──▶ ADS ──Sqoop──▶ MySQL shop_ads ──▶ Vue + ECharts
     ↑                       ↑               ↑                      ↑               ↑                       ↑
  每日增量              业务源库         原始数据层              汇总层         报表层                  前端展示
```

### 关键说明

- **增量数据链**：`shop-data-mocker --daily` 每天凌晨先往 MySQL 写入今日增量数据 → Sqoop 按时间字段拉入 Hive ODS → 逐层加工 → 最终导出结果
- **全量数据链**：10 张低频变化表（如 category、shop、admin）每天 Sqoop 全量覆盖，保证维度表完整
- **调度周期**：T+1 模式，每日凌晨自动执行全链路，产出昨日经营报表

## 三、数仓分层

```
MySQL ──Sqoop──▶ ODS ──▶ DWD ──▶ DWS ──▶ ADS ──Sqoop──▶ MySQL shop_ads
                原始数据    明细事实    轻度聚合    指标报表
```

### ODS（源数据层）
- **全量表**（10 张）：address, admin, cart, category, permission, role, role_permission, shop, user_role, user_status_log — Sqoop 全量导入，每天刷新
- **增量表**（5 张）：orders, order_item, product, sku, user — 按 create_time/update_time 过滤 T+1 数据
- 格式：TEXTFILE + 分区 `dt STRING`

### DWD（明细层）
- **拉链表**（3 张）：`dwd_dim_product_zip`、`dwd_dim_sku_zip`、`dwd_dim_user_zip` — 跟踪历史变化，`end_date='9999-12-31'` 表示当前有效
- **事实表**（1 张）：`dwd_fact_order_detail` — 订单+订单项关联，退化维度（用户名、品类名），分区表

### DWS（汇总层）
- **日汇总**（4 张）：`dws_order_daily`、`dws_product_sale_daily`、`dws_shop_daily`、`dws_user_active_daily`
- 订单级去重 + 子查询替代 CTE（兼容 Hive-on-Spark）

### ADS（报表层）
- **分区表**（6 张）：ads_overview, ads_gmv_daily, ads_order_stats_daily, ads_user_active, ads_user_new_retain, ads_shop_daily
- **非分区表**（3 张）：ads_category_sales, ads_product_top50, ads_trend_weekly（全表覆盖）

## 四、ETL 流程

```
01_sqoop_ods_full ──┐
                    ├──▶ 03_dwd_etl ──▶ 04_dws_etl ──▶ 05_ads_etl ──▶ 06_ads_export
02_sqoop_ods_inc ───┘
```

| 步骤 | 说明 | 技术要点 |
|------|------|----------|
| 01 全量导入 | 10 张表 Sqoop → HDFS tmp → LOAD DATA 到 Hive 分区 | `--delete-target-dir`，覆盖当天分区 |
| 02 增量导入 | 5 张表按时间过滤增量数据 | `--where` 子句精确控制 T+1 范围 |
| 03 DWD 加工 | 拉链表关闭旧版本 + 插入新版本；事实表多表关联 | 3 个拉链表各需 2 步操作 |
| 04 DWS 汇总 | 订单级去重聚合 | Spark 引擎，子查询替代 CTE |
| 05 ADS 指标 | 9 张报表 SQL 计算 | 留存率用标量子查询 |
| 06 导出 | Hive → HDFS 临时目录 → Sqoop → MySQL | 分区表需删旧数据再插入 |

## 五、关键技术点

### 1. 拉链表（SCD Type 2）
```
关闭旧版：UPDATE end_date = today WHERE end_date = '9999-12-31' AND 有变化
插入新版：INSERT 新行，start_date = today, end_date = '9999-12-31'
```
每天 OVERWRITE 全表，重写所有行的有效期。

### 2. CTE 兼容性问题
Hive 3.1.3 + Spark 引擎 `ParseException: cannot recognize input near 'WITH'` → 全部改写为内联子查询 / 标量子查询。

### 3. Sqoop 导出方案
Hive ORC/Parquet → Sqoop 不兼容，方案：`INSERT OVERWRITE DIRECTORY` 写出 TEXTFILE 到 HDFS 临时目录，再 `sqoop export --direct`。

### 4. 留存率计算
```
新增用户数：WHERE start_date = today
N日留存：   WHERE start_date = date_add(today, -N)
             AND EXISTS (当天有订单)
留存率 = 留存用户 / 新增用户 × 100%
```

## 六、遇到的问题

| 问题 | 原因 | 解决 |
|------|------|------|
| Hive 表未分区但写入分区 | DDL 文件未在集群上执行 | 重新建表 `PARTITIONED BY (dt STRING)` |
| CTE ParseException | Hive-on-Spark 不识别 WITH 语法 | 全部换为子查询 |
| Sqoop 导出失败 | Hive 默认 ORC 格式不兼容 | 中间临时目录用 TEXTFILE |

## 七、产出

每天自动产出 **9 张报表**，覆盖：经营概览、GMV 日报、订单状态分布、商品 Top50、分类销售排行、用户活跃与留存、店铺日报、近 8 周趋势。
