# 检索链路降级加固 — 设计文档

> 关联代码：`RagSearchService`、`RagFallbackTest`
> 关联缺陷：嵌入模型故障时整条商品搜索返回空，与类注释宣称的降级策略不符

## 1. 背景与问题

`RagSearchService.search()` 是混合检索入口（向量 + 关键词双路 → RRF 合并）。
修复前，第 1 步「生成查询向量」阶段的四类失败全部直接 `return Collections.emptyList()`：

| 失败场景 | 修复前行为 |
|---|---|
| 嵌入模型调用异常（网络 / 鉴权 / 欠费） | 返回空列表 |
| 嵌入模型返回空列表 | 返回空列表 |
| 嵌入模型返回空向量 | 返回空列表 |
| 向量维度不符（非 1536 维） | 返回空列表 |

**后果**：DashScope 是外部依赖，抖动 / 欠费 / Key 失效时商品搜索**整体不可用**——
连「洗衣机」「冰箱」这类纯 MySQL FULLTEXT 本来就能命中的 query 也被一并拖死，
用户侧表现为搜索无结果、客服推不出商品卡片。

**与文档不符**：类注释声称「向量路异常时自动降级为纯 MySQL FULLTEXT 关键词路」，
但真正会降级的只有 `searchViaQdrant` 内部（Qdrant 挂了）；嵌入模型阶段的故障没有降级覆盖。

**与对话链路不对称**：对话侧已有三级降级（DeepSeek → qwen-plus → 无 LLM 模板兜底，见 `ChatService`），
检索侧却是单点依赖，两条链路的健壮性口径不一致。

## 2. 硬约束

1. **接口契约不变**：`search(String, int, Long, BigDecimal, BigDecimal)` 签名与返回类型不变，调用方无感。
2. **降级必须静默可用**：异常不得向上抛——上层依赖返回结果渲染商品卡片，抛异常会导致 SSE 流中断。
3. **不改 Qdrant 侧既有降级**：`searchViaQdrant` 捕获异常返回空列表的行为保持不变。
4. **不改 RRF 合并语义**：`RrfMerger.merge` 对「单路为空」已有专门分支（list1 为空则直接取 list2 前 topK），
   降级后天然退化为纯关键词排序，合并逻辑无需改动。
5. **不新增外部依赖。**
6. **不改变正常路径行为**：嵌入模型正常时，向量路入参、minScore、limit 与 RRF 合并结果与修复前完全一致。

## 3. 入参与返回

| 项 | 说明 |
|---|---|
| `query` | 用户查询串；null / 空白直接返回空列表（保持原行为） |
| `topK` | 返回条数，链路固定传 5 |
| `categoryId` / `minPrice` / `maxPrice` | 过滤条件，透传给向量路（关键词路不做过滤，保持原行为） |
| 返回 | `List<RagHitVO>`，按 RRF 分数降序；**仅当两路皆空时**返回空列表 |

## 4. 错误处理矩阵（修复后）

| 故障点 | 行为 | 日志 |
|---|---|---|
| 嵌入模型调用异常 | 跳过向量路，关键词路兜底 | `WARN [RAG降级] 调用失败` |
| 嵌入模型返回空列表 | 同上 | `WARN [RAG降级] 空列表` |
| 嵌入模型返回空向量 | 同上 | `WARN [RAG降级] 空向量` |
| 向量维度不符 | 同上 | `WARN [RAG降级] 维度不匹配` |
| Qdrant 不可用 | `searchViaQdrant` 返回空，关键词路兜底 | `WARN Qdrant 不可用，已降级` |
| 关键词路 SQL 异常 | `KeywordSearchService` 内部捕获返回空 | `WARN MySQL FULLTEXT 检索异常` |
| 两路皆空 | 返回空列表 | `INFO [RAG指标] 合并0条` |

埋点补充：`[RAG指标]` 日志新增 `向量路=正常/已降级(纯关键词)` 字段，线上可直接统计降级率。

## 5. 容易踩的坑

1. **`RrfMerger.merge` 的短路分支必须存在**。降级依赖「list1 为空时直接返回 list2 的前 topK」；
   若将来把合并改成「两路都非空才合并」，降级会静默返回空。当前已确认该分支存在（`RrfMerger` 第 29-31 行）。
2. **降级后召回质量会下降，这是有意的取舍**。实测同义词类 query：关闭扩展开，
   纯关键词 Recall@3 = 0.333 vs 混合 0.567；开启扩展后 0.800 vs 0.833。
   可用性优先于质量——返回次优结果远好于返回空。
3. **无网环境下接口会变慢**。OpenAI client 默认重试 + 2 分钟超时，降级要等重试跑完才触发，
   故障期内搜索耗时被拉长。这是可接受代价，但排查时要知道「变慢」不等于「没降级」。
4. **不要吞掉异常信息**。`log.warn` 必须带 `e.getMessage()`，否则线上无法区分网络故障与鉴权失败。
5. **维度校验语义变了**。修复前维度不符是「跳过检索」（返回空），修复后是「降级检索」；
   若将来换用非 1536 维模型，系统会静默走纯关键词而非报错，需靠日志发现。

## 6. 验收方式

1. **单测**（`RagFallbackTest`，纯 Mockito、不依赖 MySQL/Qdrant/外网，CI 可跑）：
   - 嵌入模型抛异常 → 断言返回非空、结果来自关键词路、且**未访问**向量库（`verifyNoInteractions`）
   - 嵌入模型返回空列表 → 同上
   - 向量维度不符 → 同上
2. **回归**：`RagEvaluationTest` 需仍通过，且三项指标与修复前一致（证明正常路径无回归）。
3. **反例验证**（可选）：把 `rag.llm.api-key` 置为无效值跑 `RagEvaluationTest`，
   应输出接近纯关键词路的指标（而非全 0），证明端到端降级生效。
