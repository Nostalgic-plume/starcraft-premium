# 检索链路降级加固 — 计划书

> 设计文档：`docs/rag-fallback-design.md`

## 子任务与验收

| # | 子任务 | 产出 / 改动 | 验收方式 |
|---|---|---|---|
| 1 | 提取向量生成逻辑为可降级方法 | `RagSearchService.embedQueryOrNull()`，四类失败返回 null 不抛异常 | 无 `return Collections.emptyList()` 残留在向量生成段 |
| 2 | `search()` 主流程改为降级不中断 | 向量为 null 时置空列表，继续走关键词 + RRF | 编译通过 |
| 3 | 同步类注释与埋点日志 | 类注释「降级策略」改为两级准确描述；`[RAG指标]` 增加 `向量路=` 字段 | 注释与代码行为一致 |
| 4 | 补降级单测 | `RagFallbackTest`（3 例，纯 Mockito） | `mvn test -Dtest=RagFallbackTest` 全绿 |
| 5 | 正常路径回归 | — | `mvn test -Dtest=RagEvaluationTest` 通过，指标不变 |

## 执行顺序

1 → 2 → 3（同一文件，一次改完）→ 4 → 5。

## 风险与回滚

- **风险**：改动检索主链路，若降级逻辑写错可能让正常路径也退化。
  **缓解**：第 5 项回归对比修复前三项指标，必须完全一致。
- **回滚**：单文件改动（`RagSearchService.java`）+ 新增测试文件，`git revert` 即可。
