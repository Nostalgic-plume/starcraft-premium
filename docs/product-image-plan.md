# 商品图片生成 — 计划书

> 创建日期：2026-10-14
> 关联设计：`docs/product-image-design.md`

## 任务拆解

按**依赖关系**分 3 批：先验证基建（T1），再产出文件（T2~T4），最后回填与验收（T5~T8）。
每批结束都有独立验收点，前批不过不进后批。

### 批次一：前置验证

**T1 验证 Nginx 能返回 SVG**
- 手工写一张测试 SVG 到 `D:/claudecode/shop/uploads/mock/`，`curl -I` 确认返回 200 + `image/svg+xml`。
- 验收：curl 状态码 200，Content-Type 含 `svg`。

### 批次二：生成图片文件

**T2 编写生成器**
- 新增 `shop-data-mocker/src/main/java/com/shop/mocker/ProductImageGenerator.java`。
- 含：主题推断（关键词表）、文字折行与字号自适应、SVG 渲染（主图 / 轮播 3 变体 / SKU 图）、`.env` 配置回落、XML 转义。
- 验收：`mvn compile` 通过。

**T3 小批量试跑 + 视觉验收**
- `--limit=10 --files-only` 生成约 40 张图。
- 用 Edge 无头模式截图渲染结果，确认主题配色、折行、字号、水印均正常。
- 验收：截图无排版溢出、无文字截断异常、配色与商品名匹配。

**T4 全量生成 7000 张文件**
- 去掉 limit 跑全量，统计文件数。
- 验收：`uploads/mock/product/` 下 3000 个、`uploads/mock/sku/` 下 4000 个，合计 7000。
  （覆盖全部 1000 个商品，含 33 个已逻辑删除的 —— 理由见 T7。）

### 批次三：回填与验收

**T5 回填 `product` 表**
- `main_image` + `images`（JSON 数组）两列。
- 验收：967 条 `main_image LIKE '/uploads%'`；`images` 抽查可被 JSON 解析。

**T6 回填 `sku` 表**
- `image` 列（全表）。
- 验收：4000 条 `image LIKE '/uploads%'`。

**T7 回填 `order_item` 快照**
- 单条 JOIN UPDATE 批量回填 90000 条。
- 验收：90000 条 `product_main_image LIKE '/uploads%'`。

**T8 端到端验收**
- 后端无需重启（数据即时生效）；清 Redis 商品详情缓存（逻辑过期缓存，避免读到旧值）。
- 浏览器打开用户端首页 / 商品列表 / 商品详情 / SKU 选择器，逐页截图确认无裂图。
- 验收：6 项数据校验全过 + 页面截图无裂图。

## 风险与回滚

| 风险 | 应对 |
|------|------|
| 生成图视觉不佳 | T3 设独立验收点，不满意只重跑生成，尚未碰 DB |
| 回填后想还原旧 URL | 旧值本身就是坏的，无需回滚；如需重来直接重跑生成器（幂等） |
| 订单快照 UPDATE 锁表 | 90000 行 JOIN UPDATE 在本地库约数秒，低风险 |
| Redis 缓存旧 URL | T8 显式清 `product:detail:*` 键 |

## 明确不做

- 不修 `first_category_id` 全 0、分类/品牌错配等数据质量问题（用户已确认本次只做图）。
- 不改后端 / 前端任何代码。
- 不引入绘图库或字体文件。

### 主题覆盖质量

初版关键词表有 **109 个商品走兜底**（未匹配任何主题）。经 3 轮「`--analyze` 全库核查 → 按实际商品名修正关键词 → 复跑」，最终：

**967 个有效商品全部归入 15 个主题，兜底 = 0。** 分布：家电 173 / 数码 131 / 食品 129 / 家居 102 / 电脑 79 / 美妆 75 / 图书 66 / 服饰 57 / 运动 50 / 母婴 47 / 影音 35 / 鞋包 14 / 穿戴 5 / 医药 2 / 汽车 2。

核查中修正的典型误匹配（均源于关键词过宽或被更靠前主题劫走）：

| 商品 | 误判为 | 修正后 | 原因 |
|------|--------|--------|------|
| 九阳 破壁**料理机** | 兜底 | 家电 | 关键词写作"破壁机"，漏了"破壁料理机" |
| 花王 婴儿纸尿**裤** | 服饰 | 母婴 | "裤"命中服饰；新增母婴主题并前置 |
| 农夫山泉 天然水 整**箱** | 鞋包 | 食品 | "箱"过宽；收窄为"行李箱/拉杆箱" |
| 东鹏特饮 **维生素**功能饮料 | 医药 | 食品 | "维生素"过宽；收窄为"维生素片/复合维生素" |
| 蕉下 女士**防晒**衣 | 美妆 | 服饰 | "防晒"过宽；收窄为"防晒霜/防晒乳" |
| 珂拉琪 **唇釉** | 兜底 | 美妆 | "唇膏"漏了"唇釉" |

**方法论沉淀**：关键词表**顺序即优先级** —— 宽泛主题（食品的"油"、服饰的"裤"）必须排在特定主题（汽车"机油"、母婴"纸尿裤"）之后。此规则已写入代码注释。

### 过程中的问题与处置

| 问题 | 处置 |
|------|------|
| `-Dexec.mainClass` 无法覆盖 pom 中写死的 `mainClass`，误跑了旧工具 `DataMockerApplication` | 改用 `java -cp target/classes;$(cat target/cp.txt)` 显式指定类名。**已核查：数据库无脏数据**（它在该批插入的首条 SQL 即报错，未写入任何行） |
| `order_item` 2833 条未回填 | 根因是漏掉已逻辑删除的商品；改为不过滤 `deleted` 后全部覆盖 |
| 自检 SQL 把 `images` 当单值判断（`LIKE '/uploads/%'`），恒为 0 | JSON 数组以 `[` 开头，改为 `LIKE '%/uploads/%'` |
| 后端启动报 `ClassFormatError: RagProperties` | 增量编译残留，`clean install` 后恢复（与本次改动无关） |
| 后端启动报 MySQL `Access denied` | `spring-boot:run` 工作目录是模块目录，读不到仓库根 `.env`；用 `-Dspring-boot.run.workingDirectory=D:/claudecode/shop` 解决 |
| 文档记录的测试账号 `zhangsan`/`lisi` 不存在 | 库中为 mock 生成的 `user_xxxxxx` 账号且多为禁登状态；为完成页面验证注册了临时账号 `imgcheck` / `123456` |
