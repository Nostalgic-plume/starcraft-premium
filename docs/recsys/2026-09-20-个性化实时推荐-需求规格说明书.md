# 基于实时特征的个性化商品推荐系统

## 需求规格说明书

## 1 项目背景

### 1.1 业务概述

商城首页热销榜单是平台核心流量入口，承担商品曝光、用户消费引导的核心作用。目前商城首页采用**全局静态热销榜单**展示模式，面向所有用户展示统一的商品排序，榜单仅依据商品整体热度生成，未结合用户个人浏览、点击等行为偏好做差异化适配。平台已具备完善的用户行为采集能力，可记录用户首页浏览、商品点击等行为数据。

### 1.2  业务现状与痛点

当前静态榜单展示模式存在明显业务短板，无法适配精细化运营需求：

1. **用户侧体验问题**：全体用户共享同一套榜单，无个性化差异，用户需要逐条筛选商品，查找成本高、精准度低，容易降低浏览意愿与下单转化率。
2. **数据价值浪费问题**：平台采集的海量用户行为数据仅用于离线统计、报表展示，未实现线上数据回流，无法反哺首页推荐业务，数据利用率极低。
3. **平台与商家流量问题**：固定固化的榜单排序导致流量高度集中，无法实现兴趣匹配分发，商家商品难以精准触达目标客群，优质长尾商品曝光不足，整体流量转化效率偏低。

### 1.3 项目建设意义

为解决静态榜单的体验短板与数据闲置问题，本次项目将打通用户行为数据回流链路，实现首页热销榜单的**个性化动态重排能力**。
项目建设完成后，可基于用户个体行为偏好差异化展示榜单内容，在用户侧大幅降低商品筛选成本、提升浏览体验；在商家侧实现商品精准兴趣曝光，提升销量与经营收益；在平台侧盘活存量行为数据，提升首页流量利用率与整体业务转化效率。

## 2 系统边界与数据来源

### 2.1 系统边界

本项目为星创优品商城的个性化推荐子系统，属于**新增辅助功能模块**，不改动商城原有业务架构。系统不参与商品上架、订单交易、支付结算、购物车管理等核心业务，仅负责用户行为数据分析与个性化榜单生成。

系统输入为用户行为日志、商品基础信息与用户评价数据；系统输出为个性化排序后的商品推荐列表，供商城首页展示。整体能力独立解耦，不侵入原有商城业务流程。

### 2.2 数据来源

本系统所有分析与计算数据均来自商城业务数据，主要包含三类：

1. 用户行为数据：采集用户在商城页面的浏览、加购、收藏、购买行为，是系统特征计算与画像生成的核心数据源。
2. 商品基础数据：包含商品名称、商品描述、类目信息等静态商品资料。
3. 用户评价数据：用户对商品的评价文本摘要，用于辅助构建商品语义特征与用户偏好画像。

本项目全部数据为模拟合成数据，无真实用户隐私信息，满足数据安全合规要求。


### 2.3 用户与业务场景

**场景一：游客访问**。未登录用户打开首页时，系统无法识别其身份与历史偏好，查询接口直接返回热门榜单内容；页面不出现空白或报错，浏览体验与改造前保持一致。

**场景二：冷启动新用户**。用户已注册登录但没有任何历史行为，语义召回与协同过滤召回均无有效输入，系统依靠热门兜底返回非空候选集；待其产生首次行为后，再逐步纳入个性化计算。

**场景三：有行为的老用户**。用户近期浏览过某类目商品，行为经采集写入行为队列后，实时特征在 5 秒内完成更新；再次打开首页时，候选集按实时特征与画像重新排序，列表顺序与上次访问不同。

**场景四：服务降级**。模型服务超时或向量检索不可用时，系统按预设策略降级：画像沿用上一版、重排退回规则排序结果、召回降级为热门兜底；接口仍返回非空商品列表并标记降级状态，不出现空白页或请求挂起。

### 2.4 术语说明

| 术语 | 业务含义 |
|---|---|
| 事件时间 | 行为实际发生的时刻，由上报数据携带，计算以它为准，不使用数据到达系统的时刻 |
| 滑动窗口 | 以当前时刻为终点、向前追溯固定时长的时间区间，用于统计用户近期行为 |
| 实时特征 | 由用户近期行为在秒级聚合出的数值，用于影响当次推荐结果 |
| 用户画像 | 对用户偏好的一段自然语言描述，由行为序列与评价文本归纳得到 |
| 候选集 | 召回环节筛出的待排序商品集合，尚未确定最终展示顺序 |
| 语义召回 | 按含义相近程度检索商品，而不是匹配关键词 |
| 协同过滤召回 | 依据相似用户或相似商品的交互行为找出商品 |
| 热门兜底 | 以近期热度榜作为保底结果，保证任何情况下都有商品可返回 |
| 冷启动 | 用户没有任何历史行为、无法计算个性化特征的状态 |
| 负反馈 | 用户主动表达的不感兴趣，用于将对应商品排除出推荐列表 |
| 消融对比 | 逐项增减功能模块并对比指标增量，用于说明各模块的实际贡献 |

## 3 功能需求

本章描述个性化榜单重排模块需要实现的业务功能，模块作为商城新增能力，不改动商城原有商品浏览、下单支付等基础业务功能。
### 3.1 行为采集与加速回放

 采集用户在商品详情、购物车、收藏、下单页面的浏览、加购、收藏、购买四类行为，通过上报接口提交商城后端，作为行为数据唯一来源。

 行为事件携带带时区 ISO 8601 格式的发生时间，后端校验字段后写入行为队列并即刻返回，不阻塞下游。

 上报失败支持前端重试；支持历史行为加速回放，回放保持事件时序，不丢弃事件。


### 3.2 实时行为特征计算

 消费行为事件流，通过滑动窗口统计用户不同时段行为频次、类目偏好特征。

 以行为发生事件时间计算窗口，规避网络乱序带来统计错误。

 计算结果存入特征存储并设置有效期，供召回读取；单条写入失败不中断主链路。


### 3.3 用户画像更新

汇聚用户行为序列、评价文本，通过模型生成自然语言画像，供语义召回、个性化重排使用。

合并用户 5 秒内重复行为，控制模型调用成本；画像仅记录商品偏好，不推断敏感属性。

画像持久化存储，至少保留 3 个历史版本；画像生成失败自动沿用上个有效版本。


### 3.4 商品向量索引构建

读取商品名称、描述、评价摘要，生成商品向量并构建语义索引，实现语义检索。

商品信息变更时批量更新索引；更新过程线上查询使用旧索引，服务不中断。

索引和商品状态保持一致，剔除已下架商品；向量维度固定，运行过程不可修改。


### 3.5 多路召回与融合

推荐请求并行执行语义召回、协同过滤召回、热门兜底召回，保证一定返回候选商品。

多路召回结果去重、融合，统一得分量纲，召回权重支持配置。

过滤已购、已加购、已下架商品；冷启动依靠热门兜底返回商品；单路召回异常时使用其余链路结果继续执行。


### 3.6 个性化重排

对候选商品先做规则打分排序，再交由模型完成重排，输出首页最终商品顺序。

重排仅可操作候选集内部商品；模型调用超时或校验失败，自动退回规则排序结果。

增加类目占比限制、过滤负反馈商品；生成推荐理由，理由生成失败不影响商品列表返回。


### 3.7 推荐结果查询服务

对外提供查询接口，返回排序后的商品列表以及推荐来源和理由，供首页推荐区块渲染。

接口校验登录态；结果支持缓存，画像更新后缓存失效。

查询 P95 耗时≤800ms；出现异常自动降级，不返回空白页面；游客直接返回热门榜单。


### 3.8 离线评测与消融对比

基于时间切分评测数据集，在基线和多种推荐策略配置下批量执行评测。

采用时间切分方式，禁止随机划分数据集，保证各组实验使用同一套评测数据。

计算 Recall@10、NDCG@10、覆盖率，区分活跃用户与冷启动用户，输出消融对比报告。

### 3.9 需求优先级

按「是否影响端到端链路跑通与验收取证」划分优先级：核心必做项构成最小可用闭环；拓展可选项目均内置降级路径，缺失时不影响系统可用性与验收结论。

| 优先级 | 功能项 | 判定依据 |
|---|---|---|
| 核心必做 | 3.1 行为采集与加速回放、3.2 实时行为特征计算、3.4 商品向量索引构建、3.5 多路召回与融合、3.7 推荐结果查询服务 | 构成「采集—计算—召回—展示」的最小可用闭环，缺任一项链路中断 |
| 核心必做 | 3.8 离线评测与消融对比 | 唯一产出效果指标与模块增益证据的环节，直接决定验收结论 |
| 拓展可选 | 3.3 用户画像更新 | 无画像时语义召回可退回协同过滤与热门兜底，链路仍可用 |
| 拓展可选 | 3.6 个性化重排 | 已内置超时与校验失败降级，退回规则排序仍可正常返回列表 |

## 4 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 推荐请求 P95 不超过 800ms；召回环节耗时不超过 150ms；行为上报接口响应不超过 100ms |
| 时效性 | 用户行为产生后，5 秒内完成特征计算并生效，可影响后续推荐结果 |
| 容量 | 可支撑至少 100 万条行为数据；覆盖全部商品与用户数据；满足课程演示与小规模并发访问 |
| 可靠性 | 任意环节异常时仍需要返回有效结果，禁止页面空白或请求卡死。画像归纳失败保留上一版画像；向量检索失败降级至热门兜底；特征读取失败按无特征处理；单路召回失败则使用其余链路结果继续执行|
| 安全合规 | 推荐接口校验登录态，用户仅可查看自身的推荐结果；用户画像不推断敏感属性；项目所用数据均为合成数据，不包含真实用户隐私信息 |

## 5 约束与假设

### 5.1 约束条件

1. 环境约束：系统基于单机环境开发运行，内存上限 16GB，仅适用于课程演示和小规模数据评测，不支持大规模并发与生产级部署。
2. 技术约束：实时特征计算依赖流式实时计算逻辑，系统处理时序数据以行为发生事件时间为准。
3. 业务约束：系统仅对首页榜单做个性化重排，不修改商城原有商品、订单、交易逻辑。
4. 数据约束：商品向量维度固定，系统运行过程中不允许动态变更。

### 5.2 前提假设

1. 合成模拟数据集分布合理，能够有效模拟真实用户浏览与消费行为，可用于需求验证与离线评测。
2. 商城基础服务稳定，可正常提供商品信息、用户行为、评价数据等基础数据源。
3. 外部模型服务可正常完成文本向量化、用户画像归纳任务，保障推荐链路正常运行。
4. 允许网络传输存在少量行为乱序，系统可通过事件时间机制正常适配处理。

### 5.3 风险分析

1. 资源风险：宿主机内存上限 16GB，实时计算、向量索引与模型调用同机部署时可能出现内存不足。应对措施：控制演示与评测的数据规模，各环节错峰启动，必要时降低并发与批量大小。
2. 外部依赖风险：画像归纳、文本向量化与个性化重排均依赖外部模型服务，服务不可用或响应超时会直接拖慢推荐链路。应对措施：全链路预设降级策略——画像沿用上一版、重排退回规则排序、向量检索失败降级热门兜底，接口始终返回非空结果。
3. 数据与评测风险：行为与评价数据均为合成数据，其分布与真实用户行为存在偏差，可能导致离线指标虚高、结论失真。应对措施：评测集按事件时间切分，活跃用户与冷启动用户分别统计，关键结论辅以人工抽样核对。

## 6 预期业务效果

系统上线后，首页商品列表由全局静态榜单改为按用户个体行为偏好动态重排，预期产生以下可量化效果：

- 效果提升：相对静态热销榜单基线，离线评测 Recall@10 相对提升不低于 30%，NDCG@10 同步提升；
- 响应时效：推荐请求 P95 不超过 800ms，用户行为发生后 5 秒内即可影响推荐结果；
- 流量结构：流量不再集中于少数热销商品，长尾商品获得更多兴趣匹配的曝光机会；
- 数据价值：用户行为数据由离线统计转为线上回流，形成「采集—计算—推荐」的数据闭环。

以上指标基于合成数据与离线评测得出，用于验证链路正确性与模块增益，不代表真实生产环境下的线上效果。
