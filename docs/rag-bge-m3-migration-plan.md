# RAG 向量路迁移执行计划书

> 设计依据：`docs/rag-bge-m3-migration-design.md`

## 顺序原则

用户已定序：**先定数据 → 再切模型 → 最后建索引**（索引只重建一次）。

```
批次1 环境 ──┐
             ├──▶ 批次3 代码 ──▶ 批次4 切换重建 ──▶ 批次5 验收
批次2 数据 ──┘
```

批次 1（TEI）与批次 2（数据）**互不依赖，可并行**；批次 3 也不依赖数据，可提前写。只有批次 4 必须等前三批全部就绪。

## 子任务

| # | 任务 | 依赖 | 验收方式 |
|---|------|------|----------|
| **T1** | Docker 起 TEI（BGE-M3，GPU） | 无 | `GET /health` 通过；`POST /v1/embeddings` 返回**恰好 1024** 个浮点数 |
| **T2** | DataForge 重新生成 shop 数据 | 无 | 数据落库；外键/规则校验通过；记录各表行数作为索引基数 |
| **T3** | `RagProperties` 加 3 个字段（`embeddingBaseUrl`/`embeddingApiKey`/`backupBaseUrl`），`dimension` 默认值 1536→1024 | 无 | `mvn compile` 通过 |
| **T4** | `RagConfig` 两个 bean 的 `baseUrl` 由硬编码改为读配置 | T3 | 编译通过；启动日志打印实际端点（需临时加日志或断点确认） |
| **T5** | 换备用模型供应商（qwen-plus 的 DashScope 替代） | 决策 | 直接调用备用模型成功返回；熔断测试能走到备用路 |
| **T6** | 触发全量重建：确认 TEI 就绪 → `POST /api/index/rebuild` | T1+T2+T4 | Qdrant 集合 `size=1024` 且 `points_count` = 上架商品数 |
| **T7** | 重建评估集（query → 期望商品标注） | T2 | ✅ 2026-09-27 核验：商品数据未被替换，原标注与当前商品名/ID 仍匹配（54 个期望 ID 逐一核对，仅 137 因下架不合规），**无需重建** |
| **T8** | 重跑评估，对比基线 | T6+T7 | ✅ 2026-09-27 完成：生产档基础集 **Recall@3 0.711 = 0.711（持平，不回退）**；基线更正与结论见 `docs/rag-evaluation-report.md` §9 |

## 关键执行约束

### T6 前必须确认
1. **TEI `/health` 通过** —— `doRebuild()` 首步会**先删集合**，TEI 不可用则数据补不回来
2. **`rebuildAll()` 启动钩子不会自动重建**（集合已有数据即跳过），必须用 `POST /api/index/rebuild` 走 `forceRebuildAll()`

### T2 的时间盒（重要）
DataForge 首次跑真实场景，失败概率不低（规则覆盖不全 / 收敛不达标 / 表关联遗漏）。
**建议给 T2 设明确时间盒（1~2 天）**：超时则改用现有数据继续 T3~T8 —— 索引大不了重建两次（278 条，秒级），**不能为了省一次重建卡住整条链**。

### T8 是决策点
若新指标**显著低于**基线，需在此停下来评估：回退（设计文档 §7）／调 RRF 权重／调整索引文本构造。
**不要默认"换了新的就一定更好"** —— 已有公开实验显示 BGE-M3 在部分语料上 Recall 回退。

## 遗留决策（需你确认）

1. **备用模型换哪家**（T5）—— 建议选与 DeepSeek 不同供应商的 Qwen 兼容端点，保留"主备异构"的容灾语义
2. **是否同时放宽 `MAX_DETAIL_LENGTH=500`** —— BGE-M3 上下文 8192，可让商品长描述完整入库（设计文档 §6.7）
3. **是否启用 Qdrant MCP**（设计文档 §6.6）—— 建议放在 T8 之后，且必须做一致性验证
